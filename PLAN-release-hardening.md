# PLAN: Release hardening — app icon, ad-hoc signing, packaged smoke gate (rank 5)

**Execution order:** independent of the other plans; run it after plans 1–4. `PLAN-final-polish.md` is the only plan that comes after this one.
**Effort:** ~3 hours. **Files touched:** `scripts/generate-app-icon.mjs` (new), `forge.config.ts`, `scripts/package-release.sh`, `.gitignore`, `assets/app-icon.icns` (generated, committed). Nothing else.

## Goal

The DMG currently ships an app with the **default Electron icon** and an effectively unsigned bundle whose Resources are modified *after* packaging (media is ditto'd in), so the bundle seal is inconsistent, and nothing verifies the staged app actually boots before the DMG is built. Three fixes:

1. A real Campfire app icon (`.icns`), generated by a dependency-free script in the same spirit as `scripts/generate-tray-icons.mjs`.
2. Ad-hoc code signing of the staged app **after** media is added, so the bundle verifies cleanly (`codesign --verify`) for local/personal distribution. (Notarization/Developer-ID is out of scope — no Apple account assumed.)
3. `scripts/package-release.sh` runs the existing built-in launch proof (`CAMPFIRE_LAUNCH_PROOF=1`, already implemented in `src/main.ts` as `runLaunchProof`) against the staged app and aborts the release if it fails.

## Step-by-step

### Step 1 — `scripts/generate-app-icon.mjs` (new file)

Model it on `scripts/generate-tray-icons.mjs`, which already contains a zero-dependency PNG encoder (`crc32`, `chunk`, `png`) and a flame-shape rasterizer (`makeIcon`). Copy those helpers into the new script (do not import across script files; keep each script self-contained like the existing one), then extend:

1. **Color support:** the tray script writes black pixels with variable alpha. Generalize `setPixel(rgba, width, x, y, alpha)` to `setPixel(rgba, width, x, y, r, g, b, alpha)` in the copied version.
2. **Icon drawing** — `makeAppIcon(size)`:
   - Fully transparent canvas.
   - Rounded-rect background: inset `8%` of `size` on all sides, corner radius `22%` of the rect's width, filled `#1c1917` (stone-900). Implement rounded-rect coverage per pixel: inside if within the inset box AND (not in a corner square OR within radius of that corner's center) — same brute-force per-pixel style the tray script uses; icons are ≤1024², speed is irrelevant.
   - Flame glyph: reuse the tray script's flame-shape math (the `insideOuter` / `insideCutout` block from `makeIcon`, with `active = false` so the flame has its cutout), scaled to occupy the middle ~55% of the icon (map the glyph's 0–1 `nx/ny` space onto a square of side `0.55 * size` centered horizontally, vertically centered slightly high at `0.47 * size`). Fill `#fbbf24` (amber-400).
   - Skip the tray script's crossed-logs lines and the ember dot — just background + flame reads better at icon sizes.
3. **Iconset + icns:** write PNGs into `assets/app-icon.iconset/` with Apple's exact required names, then convert:

```js
const sizes = [
  ['icon_16x16.png', 16], ['icon_16x16@2x.png', 32],
  ['icon_32x32.png', 32], ['icon_32x32@2x.png', 64],
  ['icon_128x128.png', 128], ['icon_128x128@2x.png', 256],
  ['icon_256x256.png', 256], ['icon_256x256@2x.png', 512],
  ['icon_512x512.png', 512], ['icon_512x512@2x.png', 1024],
];
// write each, then:
execSync('iconutil -c icns assets/app-icon.iconset -o assets/app-icon.icns', { stdio: 'inherit' });
```

(`execSync` from `node:child_process`; `iconutil` ships with macOS.)

4. Run it once: `node scripts/generate-app-icon.mjs`. Commit `assets/app-icon.icns`. Add `assets/app-icon.iconset/` to `.gitignore` (intermediate output).

### Step 2 — `forge.config.ts`: use the icon

In `packagerConfig`, add `icon: 'assets/app-icon'` (no extension — packager appends `.icns` on macOS):

```ts
packagerConfig: {
  asar: true,
  icon: 'assets/app-icon',
},
```

### Step 3 — `scripts/package-release.sh`: sign after staging, then gate on launch proof

Insert **after** the three `ditto` lines and the `ln -s /Applications` line, **before** the `hdiutil create` block:

```bash
# Ad-hoc sign AFTER media is staged into Resources, so the bundle seal covers everything.
codesign --force --deep --sign - "$staged_app"
codesign --verify --deep --strict "$staged_app"

# Boot the staged app once; abort the release if it cannot reach a working popover.
proof_log="$(mktemp)"
if ! CAMPFIRE_LAUNCH_PROOF=1 "${staged_app}/Contents/MacOS/${app_name}" >"$proof_log" 2>&1; then
  echo "launch proof FAILED:" >&2
  cat "$proof_log" >&2
  exit 1
fi
grep 'CAMPFIRE_LAUNCH_PROOF_RESULT' "$proof_log"
```

Notes:
- The launch proof binary self-terminates (`runLaunchProof` calls `app.exit(...)` within ~6 s of launch), so the synchronous invocation returns promptly with its pass/fail exit code. Do not add `timeout`-style wrappers (GNU `timeout` is not on stock macOS).
- The proof briefly shows the real popover on screen — expected, it is a GUI smoke check.
- Keep `--deep`: it is deprecated for store distribution but is exactly right for ad-hoc signing an Electron bundle's nested helpers in one shot.

### Step 4 — regenerate and verify a release

```bash
node scripts/generate-app-icon.mjs
bash scripts/package-release.sh
```

## Edge cases a weaker model would miss

- **Signing order is everything.** Signing before the `ditto` of `4k loops`/`sounds`/`assets` produces a bundle whose seal does not cover Resources — `codesign --verify --strict` fails and Gatekeeper behavior gets flaky. The sign step must be the last mutation of the .app.
- **`EnableEmbeddedAsarIntegrityValidation` fuse (already on in `forge.config.ts`) is unaffected** by re-signing, because the asar itself is not modified after packaging. Do not move media into the asar "to simplify signing" — 661 MB videos inside an archive breaks streaming playback.
- **Ad-hoc signed ≠ notarized.** `spctl --assess` will still reject the app; downloads from the internet still need right-click-open once. That is accepted for this plan — do not attempt notarization workarounds.
- **Icon cache:** Finder aggressively caches icons. If the new icon does not appear on the packaged app, `touch` the .app or copy it to a new location before concluding the icon is wrong.
- **`iconutil` naming is exact** — a single misnamed file (e.g. `icon_512@2x.png`) makes it fail with a cryptic error. Use the table above verbatim.
- **The launch-proof popover requires media discovery to succeed from inside the staged bundle** — that is precisely what it is guarding (the `mediaRoot()` ancestor walk finding `Contents/Resources/4k loops`). If the proof fails with `popoverHasScene: false`-style output, the staging (`ditto`) step regressed; do not weaken the check.
- **Do not run the proof against `$out_app`** (the pre-staging package output) — it has no media and would fail by design; the staged app `$staged_app` is the artifact being shipped.

## Acceptance criteria

1. `node scripts/generate-app-icon.mjs` runs clean on a fresh checkout and produces `assets/app-icon.icns`; `assets/app-icon.iconset/` is git-ignored, the `.icns` is tracked.
2. `npm run typecheck` and `npm run lint` still pass (the new `.mjs` is not in the TS project; confirm eslint doesn't error on it — if eslint picks it up and complains, add it to `.eslintignore`).
3. `bash scripts/package-release.sh` completes end-to-end, printing a `CAMPFIRE_LAUNCH_PROOF_RESULT` line with all fields `true`, and produces `release/Campfire-1.0.0.dmg`.
4. `codesign --verify --deep --strict release/stage/Campfire.app` exits 0; `codesign -dv release/stage/Campfire.app 2>&1 | grep -q 'Signature=adhoc'` exits 0.
5. Mounting the DMG shows Campfire with the flame icon (not the Electron atom); dragging to /Applications and launching lands on the popover with scenes visible.
6. Sabotage check: temporarily rename the staged app's `Contents/Resources/4k loops` and re-run only the proof snippet by hand — it must fail non-zero (then restore). This proves the gate actually gates.
